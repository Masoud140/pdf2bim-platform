# Platform source repository (updated 2026-11-17)

- **Repository:** https://github.com/Masoud140/pdf2bim-platform (private).
- **Resume point for any new session:** `docs/NEXT_SESSION.md` on the working branch. It holds the priority list, the last verified checkpoint, the next action and the open owner queries. **Read it first**, then `docs/CURRENT_STATUS.md`.
- **Working branch:** `p4-verification` (all current work; commit and push here). Earlier stage branches are stacked below it; none merged. The owner controls `main`; merging `p4-verification` needs the owner's go-ahead.
- **Visual status:** `status/index.html` (generated from repository data).
- **Code:**
  - `pdf2bim/` — Python platform: geometry, sections, model (grillage + integrated substructure, loads, combinations, traffic), design (losses, SLS / ULS, shear / torsion, prestress checks), extraction.
  - `schema/` — bridge description format 0.2, fields, migration.
  - `standards/` — the standards register (`data/*.json`, generated by `extract_from_code.py`; authority rules in `TfNSW.json`); every entry unverified until checked against the licensed edition.
  - `app/` — local web app (`start_app.sh`): projects, runs, Loads, Moving loads, Needs review, design.
  - `studio/` — Bridge Studio (single-file showcase, `python3 studio/build.py`; published as a claude.ai artifact).
  - `projects/<id>/` — one folder per bridge: `extraction/values.py` (drawing values with sources), descriptions, comparison reports. Owner PDFs and reports are never committed.
- **Key docs (repo `docs/`):** NEXT_SESSION, CURRENT_STATUS, CHANGELOG, DECISIONS (ADR-001…072), ARCHITECTURE, DEVELOPMENT_PRINCIPLES, VERIFICATION_STRATEGY, ROADMAP, method notes (P1–P5), FORMAT_0_2_SPEC, STANDARDS_DATA_SPEC, PRESTRESS_DESIGN_RULES, STANDARDS_AGENT_CONTRACT, STANDARDS_CLAUSE_CAPTURE_PROMPT, and `docs/project_knowledge/` (repository copies of every Project knowledge doc that has no other repo copy; index `README_PROJECT_INDEX.md`).
- **Rules:**
  - Autonomous mode (ADR-018); small checkpointed stages.
  - Feature branches; never merge, force-push or overwrite.
  - Commit and push at checkpoints; verify `git ls-remote origin <branch>` equals `HEAD`.
  - Report only executed test results.
  - Update `NEXT_SESSION.md` and `CURRENT_STATUS.md` at the end of every session.
  - **Rules are kept in both places (owner instruction 2026-11-17):** any change to a rule, method or convention is made in the repository (`docs/`, authoritative) and in this Project's knowledge copy in the same session (`DEVELOPMENT_PRINCIPLES.md` §5 item 8).
